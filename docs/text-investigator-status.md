# Text investigator — 2026-10-10

The application combines the existing real stdio MCP client, read-only telemetry, hybrid runbook retrieval and a direct Groq adapter. No LangChain/LangGraph, arbitrary SQL, shell tools or remediation were added. React/Vite serves one incident workbench from the Fastify container on loopback port 3002. Sarvam voice is planned, not implemented.

## Configuration and isolation

`npm run investigator:setup` creates an ignored `.env.model` with a random local API bearer token and requests disabled. Set the Groq key locally, enable requests, and run `npm run investigator:start`. The browser uses the local API token in memory; it never receives the Groq key. Model keys and private files are excluded from the image and Git. The investigator container receives the key as server configuration, restricted runtime DB credentials, and read-only local embedding weights. It contains no admin/evaluator credentials, raw data files or private mappings. Public model metadata and compiled RAG code are included in the shared runtime image.

All model evidence comes from the public MIT-licensed RCAEval benchmark; knowledge excerpts are public CC-BY Kubernetes/OpenTelemetry documentation. Automatic approval review initially misclassified the payload as sensitive/internal. Provenance was inspected, and review approved the public-data test. No rejected export was bypassed.

`GET /incidents`, `GET /investigator/status` and `POST /sessions` require bearer authentication. Session routes additionally require a random `x-session-token` capability. The selected UUID cannot change during a session. Origins must match the API host. Sessions expire after 30 minutes and are swept every minute; process restart discards them. No new database tables were added.

## Turn and response bounds

- One active turn per process; 60-second cooldown; at most 20 sessions and 10 turns/session.
- 1,000-character questions, two model calls, six MCP calls including the initial summary, 120-second total deadline.
- Individual model requests have a 30-second deadline, 1,800 completion-token ceiling, 28 KB request and 64 KB response caps. No automatic hosted retries. HTTP 429/auth failures are surfaced using sanitized codes.
- MCP has its existing server-side incident scope, read-only transactions, 15-minute maximum query window, result bounds and cancellation. Orchestration further limits result rows and evidence context; its separate 1,800-byte row budget can return fewer rows or none when a complete row is too large, explicitly marked truncated.
- Two retrieved candidate excerpts, at most 1,200 characters each, with provenance and truncation markers. Similarity is not a probability. The runbook corpus is limited and may not cover a question.
- Follow-up history is redacted and bounded to four messages. Emails, IPv4 addresses, credential patterns and configured secret values are redacted. This heuristic is not an exhaustive PII detector.
- SSE sends actual phase/tool events, never hidden reasoning or raw model drafts. Only the checked final answer is displayed. The session keeps the latest 100 events; the HTTP write buffer and browser parser are capped.

Final answers separate observations, tentative explanations, low/medium confidence, uncertainty, manual checks and documentation IDs. The final output schema offers a small set of exact excerpts drawn from collected evidence. Quotes must occur in the referenced evidence JSON or an original recorded string, and source IDs must have been retrieved. Numeric observation claims must also occur in the supporting quote. Unsupported numeric prose is replaced by a neutral excerpt description, explanations are withheld, confidence becomes low and both an uncertainty notice and an output-validation event disclose this. Fabricated telemetry quotes or evidence IDs still fail the turn. Unavailable document IDs are removed together with explanations, confidence is lowered and an uncertainty notice explains the withheld documentation support. The final schema restricts document IDs to this turn’s retrieved sources; empty retrieval requires an empty citation list, and prior-turn sources must be retrieved again. These checks validate references and selected numeric claims; they do not establish complete semantic support or causal correctness.

The final request uses Groq's strict JSON schema without tools, because [Groq structured outputs](https://console.groq.com/docs/structured-outputs) do not support combining that mode with tool use or streaming. Tool selection happens in the first request. This intentionally small loop supports a sample investigation and follow-ups, not an exhaustive scan of an entire incident. Default MCP windows cover only the first five minutes unless explicit bounds are supplied.

## Verification

The unit checks cover fabricated evidence/source IDs, malformed answers, numeric claims, redaction, no retries on provider rate limits, structured output request construction, malicious/cross-incident tool requests and redacted history. Explicitly synthetic model fixtures exercise the real authenticated API, real stdio MCP, actual benchmark logs, local embeddings and retrieved official runbooks. They are not model quality measurements.

The live reports record actual Groq usage and phase timings. An earlier report was superseded because closer review found an unsupported time-window statement; this prompted the numeric checks. The current HTTP smoke report is the packaged end-to-end result. One sample cannot establish diagnosis accuracy, latency percentiles or free-plan reliability. Development encountered a real provider rate limit, provider request/schema failures, Windows sandbox temporary-file failures and a transient MCP query timeout during a Docker build. Applicable checks were rerun after fixes and after the build completed.

Browser automation could not initialize because its tool failed to write kernel assets. HTML/assets and the real HTTP/SSE path are checked, but interactive visual QA has not been verified. Voice, held-out diagnosis evaluation, multi-process shared sessions and public deployment remain future phases.

Initial text-investigator checks: `npm run lint`, `npm run typecheck` and `npm run build` passed; `npm test` passed 35 unit checks, `npm run test:integration` passed eight service/isolation checks, `npm run test:mcp` passed six protocol checks and `npm run test:investigator` passed three real API/MCP/RAG checks. These are 52 distinct automated checks. The live standalone and packaged HTTP smoke tests also passed. The packaged nonempty-sample turn produced 12 events and completed in 4,964 ms; this is one measured sample, not a latency benchmark. Its answer references recorded evidence and retrieved official documentation. The separate empty-filter report preserves an actual abstention.

`npm run investigator:http-smoke` explicitly performs the packaged hosted test; it requires the running workbench and local `.env.model`. Both hosted smoke commands use public data, consume Groq account limits and perform no automatic retries. Provider schema errors during development included an ambiguous `anyOf` discriminator and a final-stage attempt to call a tool. The final schema uses flat ID/quote enums, displays record-only quote choices in the prompt, and treats prior tool requests as completed reference data.

## Unsupported-document fix — 2026-10-10

An interactive turn failed with `UNSUPPORTED_DOCUMENT_REFERENCE`: the output schema previously permitted arbitrary D IDs even when retrieval returned no sources. The final schema now enumerates only current-turn document IDs and requires an empty citation array for empty retrieval. Prior-turn IDs are excluded. If the provider nevertheless produces an unavailable source ID, the orchestrator withholds it and the explanations, lowers confidence and displays an explicit uncertainty notice while preserving independently verified telemetry observations. Fabricated telemetry is still rejected.

Regression checks cover no sources, some valid sources, prior-turn IDs and combined numeric/document failures. The real API/MCP/RAG integration deliberately supplies a synthetic fabricated citation and verifies an answer event with that citation withheld. `npm test` passed 39 unit checks; `npm run test:investigator` passed three integration checks; lint, typecheck and build passed. The updated container was restarted and is healthy. A live replay of the suggested log question on `88ec4733-902a-409d-8a87-5f1d744ac20e` returned verified observations, zero retrieved documents and an empty citation list, without the unsupported-document error. The sanitized report is `eval/reports/investigator-document-regression.json`. To repeat that hosted regression directly, run `node --env-file=.env.model --import tsx scripts/investigator-http-smoke.ts --document-regression` after the one-minute cooldown.
